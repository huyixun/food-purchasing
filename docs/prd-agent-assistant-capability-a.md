## 1. 一句话定位

给备料班组一个**只出建议、不写业务系统**的换算助手：把门店报的**成品份数**，按批次出成率换算成**原料公斤数**，替换掉现在每天约 3 小时的人工订货核对——但每一条建议都可追溯到口径字典的具体版本，班组长的确认或改判是流程的一部分，不是系统bug。

## 2. 背景与问题定义

### 2.1 三套口径并存（核心痛点）

| 口径 | 使用方 | 单位 | 用途 |
|---|---|---|---|
| 成品份数 | 门店、订货平台 | 份 | 报订货需求 |
| 原料公斤数 | 备料班组、生产台账 | 公斤 | 备料加工 |
| 采购公斤数 | 采购、ERP | 公斤（含皮重/损耗系数） | 下单结算 |

三个环节各算各的，靠人脑换算衔接。每天 3 小时的核对工时（访谈口径，年化约 750 小时）全部耗在「份数→公斤」上，且换算系数存在多版本（按配方、按批次、按经验），错一处就是压货或缺配。

### 2.2 为什么是"建议"而不是"自动换算"

- 批次出成率受原料实际状态影响（解冻程度、新鲜度），模型看不到现场条件；
- 换算错误的后果不可逆：压货直接变成报废损耗，缺配直接变成门店缺货；
- 试点期首要目标是建立**可信的口径分母**，不是消灭人工确认。

因此本产品的形态是：**系统出建议 → 班组长确认/改判 → 改判回写样本**。改判率是核心健康指标，而不是要消灭的对象。

## 3. 目标与非目标

### 3.1 目标（试点验收口径）

| 编号 | 目标 | 衡量方式 |
|---|---|---|
| G1 | 单品类「份数→公斤」换算建议覆盖全部订货单 | 建议覆盖率 ≥ 99% |
| G2 | 建议被班组长直接采用或仅微调（≤±5%） | 采用+微调率 ≥ 70%（M2 出基线后修正） |
| G3 | 订货核对工时从 3 小时/日降至 ≤ 1.5 小时/日 | 试点期工时抽样记录 |
| G4 | 每条建议可追溯到口径字典版本与批次 | 追溯字段完整率 100% |

### 3.2 非目标（明确不做）

- ❌ 不自动写入生产台账 / ERP / 订货平台（只读 + 出建议）；
- ❌ 不做采购量建议（那是采购口径的事，试点外）；
- ❌ 不做多品类（品类清单见 4.3，由口径字典签发决定）；
- ❌ 不替代班组长判断，不考核班组长的改判行为；
- ❌ 试点期不引入通用大模型在线推理（见 8.2 隐私约束）。

## 4. 用户与场景

### 4.1 用户角色

| 角色 | 使用方式 | 关注点 |
|---|---|---|
| 备料班组长（主用户） | 每日查看换算建议 → 确认或改判 | 建议可不可信、错了谁负责、界面能不能在备料间用 |
| 计划员 | 维护口径字典草稿、查看改判统计 | 字典版本管理、数据导出 |
| 数据/系统管理员（秦芮） | 数据健康巡检、修复队列 | 字段完整率、接口降级 |
| 供应链经理 | 签发口径字典版本 | 一改字典全部指标重算，必须受控 |

### 4.2 核心场景（每日主流程）

**场景 A：早班换算（主路径，每日 1 次）**

1. 系统 06:30 前拉取当日门店订货单（份数）与当日可用批次（含出成率）；
2. 按口径字典现行版本逐品类换算，生成建议单；
3. 班组长 07:00 前打开建议单，逐项「采用 / 微调 / 改判」；
4. 改判须填原因（下拉：现场条件 / 历史经验 / 字典不准 / 其他）；
5. 确认完成后，结果仅在本助手内留存展示，不回写业务系统；班组按确认结果备料。

**场景 B：字典缺失兜底**

品类不在口径字典现行版本内 → 该品类不出建议，标注「待签发」并计入数据健康报告。**宁可不出，不可瞎算。**

**场景 C：批次数据不全降级**

某批次缺出成率或缺状态字段 → 该批次行降级显示（灰显 + 原因标注），建议单仍可对完整批次出建议；缺失项进修复队列（秦芮）。

**场景 D：改判回写（周）**

计划员每周导出改判样本，供应商/工艺侧核对后决定是否修订字典 → 字典修订走签发流程（新版本号），历史建议的追溯指针不变。

### 4.3 首发品类

【待确认】单品类选择，候选为出成率波动小、订量大的品类；须由口径字典首版签发时一并确定。

## 5. 功能需求

### 5.1 功能清单

| 编号 | 功能 | 优先级 | 说明 |
|---|---|---|---|
| FR-A1 | 订货单拉取与解析 | P0 | 从订货平台读当日份数；解析失败走降级快照（FR-A7） |
| FR-A2 | 口径字典查询 | P0 | 按「品类+版本」取固定分母、出成率规则、排除规则 |
| FR-A3 | 批次出成率匹配 | P0 | 按「品类+批次」取当日可用批次的实测/最新出成率 |
| FR-A4 | 换算建议生成 | P0 | 份数 ÷ 分母 × 出成率修正，逐行输出建议公斤数 |
| FR-A5 | 建议单确认界面 | P0 | 逐行采用/微调/改判；改判必填原因；批量采用 |
| FR-A6 | 留痕与追溯 | P0 | 见 6.1，四段式记录 |
| FR-A7 | 接口降级快照 | P1 | 订货平台/台账不可用时，用最近一次成功快照生成建议并显著标注「非当日数据」 |
| FR-A8 | 现场草稿暂存 | P1 | 班组长确认到一半可暂存，备料间网络不稳不丢操作 |
| FR-A9 | 改判统计看板 | P1 | 按品类/原因聚合改判率，周报用 |
| FR-A10 | 字典「待签发」提示 | P2 | 未覆盖品类清单自动汇总给计划员 |

### 5.2 换算规则（FR-A4 展开）

```
建议原料公斤数 = 订货份数 ÷ 该品类标准份分母 × 批次出成率修正系数
```

- **标准份分母**：口径字典按品类定义（如 1 份 = 0.15 kg 净料），字典签发后试点期内不变；
- **批次出成率修正系数** = 实测出成率 ÷ 字典基准出成率，取该品类当日可用批次的加权值；无批次实测时取 1.0 并标注「按基准」；
- 换算结果保留 1 位小数，向上取整到 0.1 kg；
- 每行建议必须展示：份数、分母、批次号、出成率、修正系数、结果——**六个要素缺一不可**，缺任何一个该行不得出现建议值。

### 5.3 交互要点

- 主界面是一张**建议单表格**，不是聊天框：备料间是手套+噪音环境，表格逐行勾选比对话高效；
- 移动端/工位平板可用（班组长的确认动作发生在备料间，不在办公室）；
- 建议单顶部固定横幅显示：字典版本号、批次数据时间戳、是否降级快照；
- 【待确认】界面字号、持握设备形态，需现场观察后定。

## 6. 留痕、转人工与责任边界

### 6.1 四段式留痕（对齐试点方案）

每次确认/改判记录四段，缺一不成立：

```
原因（下拉枚举+可选备注） — 确认人（工号+姓名） — 确认时间（服务器时间） — 结论（采用值）
```

只有消息通知、只有点击「已读」**不算完成**。留痕记录保存 ≥ 90 天，【待确认】留存期限。

### 6.2 本能力内的转人工情形（能力 A 范围内 2 类）

| 情形 | 触发 | 处理 |
|---|---|---|
| 字典规则冲突 | 同一品类命中两条互相矛盾的规则 | 不出建议，转计划员裁决，记录裁决人 |
| 批次出成率异常 | 实测出成率偏离基准 > 【待确认，建议 ±20%】 | 不自动采用，转班组长人工判断并签核 |

> 四类完整转人工情形（含促销取消已解冻、系统不可用）属能力 B/C 范围，另立文档。

## 7. 数据需求

### 7.1 输入数据

| 数据 | 来源 | 必需字段 | 更新频率 |
|---|---|---|---|
| 门店订货单 | 订货平台 | 品类、份数、订货日期、门店 | 每日 |
| 口径字典 | 助手内维护 | 品类、分母、基准出成率、排除规则、版本号、签发人、签发时间 | 签发制 |
| 批次信息 | 生产台账 | 批次号、品类、实测出成率、状态字段、数量 | 每批次 |
| 历史建议与改判 | 本助手留存 | 全量四段留痕 | 实时 |

### 7.2 输出数据

- 每日建议单（含确认结果）：留存 90 天起；
- 改判统计周报：能力 A 不自动外发，由计划员在界面导出。

## 8. 约束与红线

### 8.1 业务红线

1. **任何情况下不得自动写入业务系统**——确认结果只在助手内留存展示；
2. 字典未签发的品类**不出建议**（宁可空白）；
3. 换算六要素不全的行**不出建议值**；
4. 字典版本变更**只增不改**：新版本生效后历史记录仍指向旧版本，保证追溯不断链。

### 8.2 数据与隐私红线

| 数据 | 红线 |
|---|---|
| 配方、出成率规则 | 商业秘密：不进任何通用大模型上下文、不出企业边界；字典存本地/私有化存储 |
| 员工留痕（工号、改判记录） | 可关联绩效与追责：限定用途声明、仅班组长本人+供应链经理可见、不做跨场景聚合分析 |
| 门店订货量 | 商业敏感：按门店授权，不做跨店聚合展示 |
| 账号 | 禁止共用账号；确认动作用强身份（工号+密码/工牌），不允许代签 |

### 8.3 技术约束

- 试点期换算逻辑用**确定性规则引擎**（查表+四则运算），不用 LLM 生成数值；LLM 只允许用于非数值的解释性文案（试点期甚至可以完全不用）；
- 所有接口读取失败必须有降级路径（FR-A7），不得出现"转圈等接口"阻塞早班流程；
- 界面必须支持弱网/断网暂存（FR-A8）。

## 9. 验收与指标（对齐试点 Gate）

| Gate | 本能力相关验收项 |
|---|---|
| M1（第 2 周末） | 批次状态字段完整率达标；字典首版签发；建议单可生成（灰度内部试用） |
| M2（第 4 周末） | 建议覆盖率 ≥ 99%；追溯字段完整率 100%；产出采用率/改判率基线 |
| M4（第 8 周末） | 采用+微调率 ≥ 70%；核对工时实测 ≤ 1.5 小时/日；改判样本完成至少 2 轮字典回写 |

**红线条目**：M1 字段完整率不达标 → 不进入 M2；期间任何红线事件（如降级快照被当真实数据使用且未发现）→ 试点暂停。
