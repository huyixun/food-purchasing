# 备料助手系统 · 一页纸需求清单

**版本** v1.0（基于 11 项评审决策冻结）｜**日期** 2026-10-30｜**阶段** 本期不进场上线，交付可运行系统 + 历史回放验证

---

## 1. 一句话定位

给中央厨房备料段一个**有自己账本、可按授权回写**的协同系统：把门店报的成品份数按批次出成率换算成原料公斤数，把短保批次的解冻与效期变成可查状态，把跨岗交接变成**对方确认接手才算完成**的待办——而不是又一个"发个通知就算办完"的群。

## 2. 用户与角色

| 角色 | 系统内定位 | 关键权限 |
|---|---|---|
| 备料班组长（主用户） | 每日确认建议、录入批次状态 | 确认/微调/改判，发起回写 |
| 采购计划员 | 维护字典草稿、分派异常、导出改判样本 | 起草、分派、导出 |
| 数据/系统管理员 | 数据健康巡检、映射与修复队列 | 主数据维护、修复处置 |
| 供应链经理 | 签发字典版本与**回写能力** | 签发、暂停试点 |
| 食安质控员 | 规则冲突裁决、异常批次隔离、否决上线 | 裁决、隔离、否决 |
| 门店配送经理 | 服务结果验收 | 只读指标与反馈 |

## 3. 核心流程（每日 1 次，06:30 前出单）

`拉取订货单（只读）` → `匹配批次与字典版本` → `生成建议单（六要素）` → `班组长逐行确认` → `本地成立 → 异步回写（两级授权）` → `异常进裁决/修复队列`

## 4. 能力清单

| 编号 | 能力 | 要点 | 优先级 |
|---|---|---|---|
| F1 | 建议单生成 | `份数 ÷ 标准份分母 × 批次出成率修正`；六要素（份数/分母/批次号/出成率/系数/结果）缺一不出值 | P0 |
| F2 | 批次台账与状态机 | 解冻状态、剩余效期、实测出成率；**备料工位扫码批量录入**，助手为权威源 | P0 |
| F3 | 短保风险提示 | 效期倒排 + 「促销取消且已解冻」场景拦截，标触发原因不标模糊提醒 | P0 |
| F4 | 建议单确认 | 采用 / 微调（≤±5%）/ 改判（必填原因枚举）；批量限于同类字段 | P0 |
| F5 | 交接待办 | 业务编号 / 版本 / 状态 / 未决事项 / 接手人五要素；**接手确认才关闭** | P0 |
| F6 | 留痕与审计重建 | 四段式（原因-确认人-服务器时间-结论）；可重建该次处理的完整链路 | P0 |
| F7 | 回写 | 两级授权 + outbox + 幂等键 + 版本校验；本地成立、异步送达 | P0 |
| F8 | 冲突与异常裁决 | 外部版本变更 → 双版本并列转人工，禁止静默覆盖 | P0 |
| F9 | 数据健康与修复队列 | 未映射、字段缺失、歧义记录、超周期待刷新 | P1 |
| F10 | 主数据与字典版本 | 品类/批次/门店码表 + 映射；字典签发制、**只增不改** | P1 |
| F11 | 历史回放器 | 重放任意历史日的订单＋批次＋当时字典版本，输出差异比对 | P1 |

## 5. 数据与集成

- **只读源**：ERP（物料/库存）、门店订货平台（份数）、生产台账（批次/加工）——15 分钟周期，超周期标「待刷新」
- **写入目标**：具备写 API 的业务系统；仅限**执行结果字段**（备料确认量、批次加工状态、交接接手人）
- **永久拒绝写入**：自助下单、效期修改、配方变更、食品检验放行
- **主数据**：助手自建三张码表 + 映射表；未映射即不出建议（宁可空白，不可瞎算）

## 6. 权限与留痕

- 禁止共用账号、禁止代签；现场终端支持短时会话与具名确认
- 数据可见范围：配方与出成率不出企业边界；门店订货量按门店授权，不做跨店聚合；员工留痕仅本人与该岗位主管可见
- 留痕只追加、不覆盖；留存期限按组织规则，**默认 ≥2 年**并支持双时态查询

## 7. 本期验收口径（不进场，改验能力而非结果）

| # | 验收项 | 判据 |
|---|---|---|
| 1 | 可追溯 | 回放 ≥10 个历史日，每条建议可指到当时的字典版本，追溯完整率 100% |
| 2 | 六要素闸门 | 构造缺字段用例，100% 拦截、不产生建议值 |
| 3 | 留痕重建 | 任取一次处理，可完整重建，四段式完整率 100% |
| 4 | 冲突安全 | 外部版本变更时自动拦回写并进裁决队列，静默覆盖 0 次 |
| 5 | 降级可用 | 断网可看快照、可确认；恢复后去重提交，重复待办 0 条 |
| 6 | 红线拒写 | 对下单/效期/配方/放行字段的写入尝试 100% 拒绝 |

> 结果指标（损耗 11%→6%、缺配 7%→2%、核对 3h→1.5h）**本期不承诺**，转入上线阶段验收。

## 8. 明确不做

- 不改配方、不放行食品、不改效期、不自主下单
- 不做采购下单建议与到货管理
- 不做门店端、配送签收与门店反馈工单
- 不用 LLM 参与任何数值计算或效期判定
- 本期不做现场上线、班组培训、扫码硬件采购

## 9. 待定与风险

| 类型 | 内容 |
|---|---|
| 待定 | 本期验证形式：内部受控试用（计划员/数据工程师/管理员用历史数据跑通全链路）——假设值，待确认 |
| 风险 1 | 批次状态需现场录入，本期不进场 → 真实录入质量与扫码可行性未验证 |
| 风险 2 | 写 API 的幂等与版本语义依赖对方系统，需尽早联调，否则 F7/F8 无法验收 |
| 风险 3 | 「所有短保批次有状态」依赖上游收货即建批次；若收货不带批次，覆盖率天然不全 |
